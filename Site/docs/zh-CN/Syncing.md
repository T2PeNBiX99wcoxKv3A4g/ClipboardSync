# 同步

## 共享的内容

| 剪贴板内容   | 状态          |
|--------------|---------------|
| 文本         | 共享          |
| URL          | 作为文本共享  |
| 图片         | 以 PNG 共享   |
| 文件和文件夹 | 以 blob 共享  |

图片受设置中的 **图片大小上限** 限制（1–32 MB，默认 10 MB）。文件和文件夹会递归遍历；一次选择受 **文件大小上限**
（默认 512 MB）和 1,000 个条目限制。

## 面板

**设备** 页面就是共享面板。每台设备连同它产生的项目一起显示，包括这台设备自己。每个项目都有传输状态：

| 状态   | 含义                               |
|--------|------------------------------------|
| 已同步 | 所有已配对设备都确认收到了该项目。 |
| 发送中 | 这台设备仍在发送。                 |
| 接收中 | 项目正从另一台设备传来。           |
| 等待中 | 对方离线，稍后会重试。             |
| 失败   | 上一次尝试没有完成。               |

项目下方会显示持有该项目的设备数量：`4 台设备中有 3 台拥有此项目。`

## 复制时的流程

1. 剪贴板监视器保存项目，并把这台设备记为来源。
2. 通过加密会话发送给所有已配对设备。
3. 每台设备保存项目、应用到自己的剪贴板，并转发给仍需要的设备。
4. 定期核对会重发尚未被确认的项目。

文件按 SHA-256 只保存一次，因此内容相同的副本共用同一个 blob。接收方只请求自己缺少的范围；连接中断后，
下一次尝试会从已写入的部分继续。放回剪贴板的视图会在文件系统允许时使用指向 blob 的硬链接。

监视器会忽略 ClipboardSync 自己造成的剪贴板变化，因此应用收到的项目不会又被发回去。

## 离线设备

离线的设备会保留自己的副本，并把尚未收到的项目显示为 **等待中**。重新连接后，定期核对和配对后的补发会填上缺少的项目；未完成的文件传输会从磁盘上已有的字节位置继续，不需要重新复制。

## 关闭同步

**设置 → 同步 → 启用同步** 只会停止发送和接收，配对关系仍会保留。可以通过 **文本和链接**、**图片** 或
**文件和文件夹** 选择共享的内容。
